# 积分优化 — 设计与实现说明（现行版）

> **文档状态**：与线上代码对齐，供日后查阅与交接。  
> **文档版本**：v2.0  
> **更新日期**：2026-07-25  
> **范围**：管理端「登录周积分优化」已上线能力；「按流水优化」仍为占位。  
> **原则**：H5 用户端无任何「优化」文案或入口，用户只看到金额变化。

---

## 0. 给甲方的白话说明（可直接转发）

商户用机具产生流水后，系统会按规则算出以后几个月要返的积分（还没领的那部分叫「待返」）。有些商户很久不登录，待返却一直挂着。

**积分优化**要做的事很简单：

1. **按「多久没登录」自动减待返**  
   商户超过整周没有登录，系统就按周把「还没领走」的待返积分往下调，每周大约保留原来的七成五（相当于砍掉约四分之一）。一直不登录，就会每周继续往下调；一旦登录了，进度重新从零计周，但**已经减掉的金额不会加回去**。

2. **可以保护指定商户**  
   运营可以把个别商户加入「白名单」，加入后这个人不参与自动下调；已经减过的也不会因为加白名单而恢复。

3. **可以随时关掉**  
   后台有一个总开关。关掉后定时任务和批量执行都不再砍；再打开时，在当前已经减过的结果上继续，不会从头重算一遍「恢复」。

4. **可以人工改某一档待返**  
   运营在后台打开某个商户的「优化调整」，能看到每一档待返金额，可以改数字、也可以勾选「这一档以后不要再自动优化」。改完后用户侧只看到新的金额，看不到「优化」字样。

5. **夜间自动跑**  
   一般每天凌晨自动对全体商户检查一遍，该减的减；白天也可以在后台预览、单户模拟或手动执行。

6. **下期另做**  
   「按流水多少来优化」还没做，目前页面只是占位，和现在这套「按登录时间」是两套独立能力。

## 1. 背景与目标

| 目标 | 说明 |
|------|------|
| 压缩长期未登录的待返 | 只动**未领取**的分期待返，不动已领入账的待提现 |
| 可审计 | 正式砍、模拟砍、改片、白名单有任务日志 |
| 可人工干预 | 按片改金额、「后续不优化」、白名单 |
| 用户无感 | H5 不出现「优化」相关说明 |

**非目标（当前不做）**

- 按流水优化（仅一级菜单占位）
- 砍已领取的待提现 / 账号积分
- H5 规则说明文案

---

## 2. 已确认业务口径（现行）

| # | 结论 |
|---|------|
| 1 | 只动未领分期待返；不动已领待提现 |
| 2 | 含当月未领（当月不特殊保护） |
| 3 | 再登录：已砍金额保留；`points_opt_week_applied` 置 0，按新登录时间重新计周 |
| 4 | 锚点：`login_time`，若无则用创建时间 |
| 5 | 未领取即可优化（含已进收益页未领的 pending） |
| 6 | 全体商户可跑；总开关控制；白名单跳过 |
| 7 | **无周数上限**：一直未登录则每周继续对剩余片 ×0.75 |
| 8 | H5 禁止优化相关文案 |
| 9 | 取整：每片 `floor(x×100)/100`（向下到分） |
| 10 | **砍法（现行）**：每个可参与自动优化的片各自 ×0.75（不再「从尾部扣差额」） |
| 11 | **人工金额片仍参与**：按当前生效值 ×0.75，砍完后清除人工，以新系统值为准 |
| 12 | **仅「后续不优化」(`opt_skip`) 的片不参与自动砍** |
| 13 | 白名单：整户跳过登录周优化；已砍不恢复；与未来「流水优化白名单」相互独立 |

**递推示例（单片）：**  
7.6 → 5.7 → 4.27 → …（每周一次，向下到分）

## 3. 核心概念

### 3.1 闲置周与已执行周

```
anchorTs = login_time || create_time
dueWeeks   = floor((now - anchorTs) / 7天)   // 应达周，无上限
applied    = points_opt_week_applied         // 已执行周（相对当前登录锚点）
```

当 `dueWeeks > applied` 时，正式执行会补砍 `applied+1 … dueWeeks` 每一周各一次，并推进 `applied`。

### 3.2 片金额四层

```
original   ← 流水规则理论值（「对账原始片」刷新）
system     ← 系统周优化后的值
manual     ← 人工覆盖（null = 无）
effective  ← manual != null ? manual : system
```

对外（冻结、待返、pending 红包）一律用 **effective**。

### 3.3 一周砍片规则（代码口径）

文件：`uniCloud-aliyun/cloudfunctions/points-optimize-admin/points-optimize.js` → `applyOneWeekCutInMemory`

对每个未领、目标月 ≥ 当前月、且 **未** `opt_skip` 的片：

1. 取当前生效值 `cur`（有人工用人工，否则用系统）
2. `nextSys = floor2(cur × 0.75)`
3. 写回 `system_amount = nextSys`，`manual_amount = null`，`effective = nextSys`

### 3.4 池为 0 是否升 applied

**升。** 无待返也把 `applied = dueWeeks`，避免日后新流水进来被一次性补砍多周。

### 3.5 再登录

1. 更新 `login_time`
2. `points_opt_week_applied = 0`（只重置进度，不恢复金额）
3. 此后从新锚点重新计周；白名单内仍跳过批跑

## 6. 管理端界面

### 6.1 积分优化页

路径：`pages/operations/points-optimize/index.vue`

| 层级 | 内容 |
|------|------|
| 一级 | 按登录时间优化｜按流水优化（占位） |
| 二级（登录） | 执行｜白名单｜任务日志 |

**执行 Tab**

- 搜索：商户编号 / 机具号
- 预览列表：商户、商户编号、白名单、闲置天、应达周、已执行、预览动作、预估砍额
- 分页：20 / 50
- 操作：积分调整、模拟、加/移白名单
- 工具：预览、执行、执行全体(续跑)、批量模拟

**任务日志（只记这些）**

- 登录周正式优化、模拟砍一周
- 总开关关闭跳过
- 人工改片 / 清人工
- 后续不优化开/关
- 白名单增删  

**不记**：对账原始片、登录重置周进度等。

### 6.2 商户列表集成

路径：`pages/merchant/list/index.vue`

| 按钮 | 说明 |
|------|------|
| 优化调整 | 本页弹窗改分片（不跳转积分优化页，避免无菜单权限无法操作） |
| 优化白名单 | 加入/移出登录周优化白名单 |

弹窗能力与优化页「积分调整」一致：按待返月分组、人工改额、后续不优化、对账原始片。弹窗头展示：白名单 / 已执行 / 应达周。

### 6.3 对账原始片

按该商户流水重算理论分片，刷新「原始」金额；**不会**把已砍的「系统」抬回原始值；未领且理论已消失的片软删；不写任务日志。成功提示：「对账成功」。

## 7. 预览 / 正式执行 / 模拟

| 模式 | 总开关 | 闲置周 | 白名单 | 是否落库 | 周进度 |
|------|--------|--------|--------|----------|--------|
| 预览 dryRun | 仅展示 | 按应达估算 | 跳过 | 否 | 否 |
| 正式执行 | 必须开 | 补砍 due−applied | 跳过 | 是 | 推进到 dueWeeks |
| 模拟砍一周 | **忽略** | **忽略**（强制 +1 周） | 仍跳过 | **真实落库** | applied+1，记 `login_week_sim` |

> 模拟用于测试砍额效果，金额会真实写入，请谨慎对生产商户批量使用。
