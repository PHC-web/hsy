# 国通星驿数据推送对接说明

本服务用于接收国通星驿侧推送的**成功交易流水、商户信息、终端信息、通讯费缴费成功**四类数据，入库并记录推送日志。提供给第三方对接的接口如下。

## 1. 基础信息

- **请求方式**：`POST`
- **Content-Type**：`application/json`
- **基础地址**：由我方提供（云函数 URL化 后的根地址，如：`https://xxx.bspapp.com/http/third-party-push`）
- **路径规则**：在基础地址后追加接口路径，例如基础地址为 `https://xxx/third-party-push` 时：
  - 成功交易流水：`https://xxx/third-party-push/TYY0001.ag`
  - 商户信息推送：`https://xxx/third-party-push/TYY0002.ag`
  - 终端信息推送：`https://xxx/third-party-push/TYY0003.ag`
  - 通讯费缴费成功：`https://xxx/third-party-push/TYY0004.ag`

> 具体基础地址以我方部署后通知为准；若使用阿里云等 path 带前缀，路径可能为 `.../third-party-push/TYY0001.ag`，以实际 URL化 配置为准。

## 2. 统一请求体格式

所有接口请求体均为 **JSON**，且与贵方《接口文档》中「数据推送」约定一致，例如：

```json
{
  "firstagentid": "61000000015114",
  "timestamp": 1695863446,
  "sign": "...",
  "apisign": "...",
  "reqdatajson": { ... }
}
```

- `firstagentid`：一级代理商编号  
- `timestamp`：时间戳（秒）  
- `sign` / `apisign`：按贵方规范  
- `reqdatajson`：具体业务数据，见下各接口说明  

## 3. 统一响应格式

| 字段        | 类型   | 说明           |
|-------------|--------|----------------|
| errorcode   | string | 00000 表示成功 |
| errormsg    | string | 错误信息       |
| timestamp   | string | 当前时间戳(秒) |

成功示例：

```json
{
  "errorcode": "00000",
  "errormsg": "推送成功",
  "timestamp": "1658460916"
}
```

## 4. 接口列表

### 4.1 成功交易流水推送 — POST …/TYY0001.ag

- **作用**：接收成功交易流水，落库并记日志。  
- **reqdatajson 字段**：与贵方文档「成功交易流水推送（TYY0001.ag）」一致（如 logno、mercid、termphyno、orderdat、ordertime、paychannel、txnamt、ysfee、ssfee、refund、discount_flag 等）。  
- **说明**：同一笔流水可多次推送，我方按每次推送各存一条记录并记日志。  
- **枚举字段（与星驿约定一致，供对账排查）**：
  - `paychannel`：`01` 支付宝，`02` 微信，`03` 银联优惠，`04` 银联未优惠，`05` 标准借记卡，`06` 标准贷记卡，`11` 冻结款(押金)，`12` 数币，`31` 京东白条，`00` 未知；若出现未列出取值请与星驿支付确认。  
  - `discount_flag`：`0` 无补贴，`1` 邮政补贴，`2` 公司补贴，`11` 落地机构补贴。  
  - `sffd`：`1` 是，`0` 否（手续费是否封顶）。  
- **落库**：除原始字段外，我方会写入解析后的 `paychannel_text`、`discount_flag_text`、`sffd_text` 便于后台展示。  
- **与后台刷卡记录**：`termphyno` 与机具管理中 `device_id`（设备编码）一致且机具已存在时，会同步写入「刷卡记录」所用流水表；机具不存在时仍完整落库 `hsy-push-trades` 并标记 `machine_in_system=false`，**不在**刷卡记录列表展示。

### 4.2 商户信息推送 — POST …/TYY0002.ag

- **作用**：接收商户信息推送，落库并记日志。  
- **reqdatajson 字段**：与贵方文档「商户信息推送（TYY0002.ag）」一致（如 agentid、mercid、mercname、applydat、status、reqdata、reqseqid、mertype、provid、cityid 等）。  
- **枚举**：`status`：`0` 开通；`1`、`2` 等为关停（非 `0` 均按关停理解）。  
- **落库**：另存 `status_text`（开通/关停）。

### 4.3 终端信息推送（含绑定/解绑）— POST …/TYY0003.ag

- **作用**：接收终端信息（绑定/解绑），落库并记日志。  
- **reqdatajson 字段**：与贵方文档「终端信息推送（TYY0003.ag）」一致（如 termno、termphyno、agentid、mercid、policyid、merextdat、equiptype、allinone、spno、merexttime 等）；`mercid` 为空表示解绑。  
- **枚举**：`equiptype`：`1` 码牌，`2` POS，`3` 音箱；`allinone`：`1` 为是，其他为否。  
- **落库**：另存 `equiptype_text`、`allinone_text`。  
- **与机具管理**：以 `termphyno` 为设备编码同步至后台「机具管理」：若不存在则**新增**一条机具，状态为**未绑定**（默认品牌取库内首条品牌）；若已存在则主要更新自有音箱号等字段。

### 4.4 通讯费缴费成功推送 — POST …/TYY0004.ag

- **作用**：接收通讯费缴费成功通知，落库并记日志。  
- **reqdatajson 字段**：与贵方文档「通讯费缴费成功推送（TYY0004.ag）」一致（如 id、mercid、policyid、feeid、feetime、receivefee、agentid、sn 等）。

## 5. 我方处理说明

- 接收：按上述路径与 JSON 请求体接收推送。  
- 存储：将 `reqdatajson` 及信封字段（如 firstagentid、timestamp）写入对应表，并保留原始 body 快照（便于对账与排查）。  
- 日志：每次推送（成功或失败）均写入推送日志表，包含推送类型、接收时间、是否成功、主键/摘要、失败原因等。  
- 响应：始终返回 HTTP 200 + 上述 JSON；业务成功时 `errorcode` 为 `00000`，失败时非 `00000` 并带 `errormsg`。  

## 6. 注意事项

- 请使用 **application/json** 提交，Body 为完整 JSON（含 `firstagentid`、`timestamp`、`reqdatajson` 等）。  
- 我方会严格校验 `apisign`：`SM3("firstagentid=<firstagentid>&sign=<sign>&timestamp=<timestamp>")`，十六进制摘要（服务端大小写不敏感比较）。  
- `sign` 字段按贵方协议传入；本服务当前仅执行 `apisign` 算法校验。  
- 具体 **基础地址** 与 **path 前缀** 以我方部署后书面通知为准。
